# repo-inventory

A read-only scanner, web dashboard, and standalone desktop application that maps every repository and project folder under a directory, shows you what is at risk of being lost, and helps you decide what to do about it. **This tool never modifies a repository.** It only reads facts and generates shell script text that you review and run yourself.

## How to run

### Standalone Desktop App (Recommended)

No background servers or ports to manage:

```bash
npm install
npm run app
```

AI chat and guidance review are optional. To configure a provider, copy
`.env.example` to `.env` and fill in either the Gemini or Bedrock credential;
never commit the populated `.env` file. The desktop settings screen can also
store provider settings in the local application configuration.

For development with hot reload:
```bash
npm run app:dev
```

To build a standalone macOS `.app` / `.dmg` installer:
```bash
npm run package:app
```

---

### Web Dashboard Mode

If you prefer browser-based serving:

```bash
# 1. Install dependencies
npm install

# 2. Build the frontend
npm run build

# 3. Start the server
npm run serve      # http://127.0.0.1:4747
```

Then open <http://127.0.0.1:4747> in your browser.

## What it looks at

The scanner walks the root directory, finds every git repository, submodule and worktree, plus any folder that contains a project manifest (package.json, pyproject.toml, go.mod, etc.). For each project it collects facts about git state, commit activity, stack and footprint.

### Flags

| Rule | Severity | Meaning |
|------|----------|---------|
| `UNPUSHED_WORK` | critical | Unpushed commits |
| `LOCAL_ONLY` | critical | No remote — exists only on this machine |
| `NOT_VERSIONED` | critical | Code with no git repository |
| `LOCAL_ONLY_BRANCHES` | warn | Branches that exist nowhere else |
| `UNCOMMITTED` | warn | Uncommitted changes |
| `BEHIND_REMOTE` | warn | Behind remote |
| `DIVERGED` | warn | Diverged from remote |
| `SCRATCH_BUT_ACTIVE` | warn | Active project living in a scratch folder |
| `NO_UPSTREAM` | info | Current branch has no upstream |
| `STALE_REFS` | info | Remote state is stale |
| `STALE` | info | No commits in 6 months |
| `ABANDONED` | info | No commits in over a year |
| `UNCOMMITTED_AND_ABANDONED` | critical | Uncommitted work in an abandoned project |
| `NO_COMMITS` | info | Repository with no commits |
| `RECLAIMABLE_SPACE` | info | Large build output |
| `NO_README` | info | No README |
| `DETACHED_HEAD` | warn | Detached HEAD |
| `HEALTHY` | good | Healthy |

## Your decisions

Two files store the data, deliberately kept separate:

- `data/inventory.json` — regenerated by every scan. It contains the facts. Gitignored, disposable.
- `data/annotations.json` — your local status, notes and snoozes. It is gitignored because it can contain private project names, paths, and workspace decisions; back it up separately if you need to preserve it.

A snooze or an `obsolete`/`archived` status hides non-critical flags, but **never** hides `UNPUSHED_WORK`, `LOCAL_ONLY`, `NOT_VERSIONED` or `UNCOMMITTED_AND_ABANDONED`. Data-loss risks remain visible even for things you have marked obsolete.

## Actions are never executed

The dashboard can generate shell scripts for bulk cleanup:

- **Publish to a remote** — for repos with no remote, produces commented-out `gh repo create` lines you edit and uncomment.
- **Move out of a scratch folder** — guarded `mv` from `tmp/` to a destination you pick.
- **Archive** — `tar` + `rm`, but only when there is no unpushed work, no uncommitted changes, and a remote exists. Otherwise it emits a refusal block.
- **Delete build output** — `find … -exec rm -rf` for `node_modules`, `.venv`, `dist`, etc.

No code under `actions/` imports `child_process` or `fs`. Actions return strings; the tool never runs them. This is the guarantee that a bug cannot destroy your work.

The one exception is **Open in** on a project's detail panel: it launches an IDE, file manager, or terminal CLI (`code`, `agy-ide`, `webstorm`, `open`, `ghostty`) on the project path via `execFile`, no shell involved. It cannot modify the repo — it just hands the path to an editor you already trust — so it runs immediately instead of producing a script. IDEs are listed in `core/ides.ts`.

## Extending it

Probes, rules and actions are loaded from `probes/`, `rules/` and `actions/` by filename order. Drop a file in, it is picked up. Delete it, it is gone. No central registry to update.

### Example probe

```ts
import type { Probe } from "../core/types.ts";

export const probe: Probe = {
  name: "example",
  order: 25,
  appliesTo: (facts) => facts.isGit === true,
  async detect({ run }) {
    const result = await run("git", ["some-command"]);
    if (!result.ok) return;
    return { someField: result.stdout.trim() };
  },
};
```
