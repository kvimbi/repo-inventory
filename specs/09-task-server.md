# TASK 09 — HTTP API server

**Goal:** `server/index.ts` — a Fastify server exposing the inventory, accepting
annotation edits, and generating action scripts.

**File you create:** `server/index.ts`

**Files you must not touch:** everything else.

---

## Public API

```ts
export interface ServerOptions {
  baseDir: string;
  port: number;
  /** Serve the built frontend from <baseDir>/dist. False in dev, where Vite serves it. */
  serveStatic: boolean;
}

/** Starts the server and returns the resolved address, e.g. "http://127.0.0.1:4747". */
export async function startServer(options: ServerOptions): Promise<string>;
```

Always bind to `127.0.0.1`. Never `0.0.0.0` — this exposes a full map of the
user's private source tree and has no authentication.

---

## In-memory state

The server holds one mutable module-level value:

```ts
let current: Inventory | null = null;
```

On startup: `current = await readInventory(baseDir)`. If that returns `null`, run
`await scan({ baseDir })` once so the first request is never met with an error.

A scan is expensive, so guard against overlapping runs:

```ts
let scanning: Promise<Inventory> | null = null;
```

A second `POST /api/scan` while one is in flight must **join** the running promise,
not start a second scan.

---

## Endpoints

### `GET /api/inventory`

Returns the current `Inventory` as JSON.

- If `current` is null, run a scan first.
- Always return through `refresh(baseDir, current)` so annotation edits and rule
  changes are reflected without a rescan.

Response: the `Inventory` object.

### `POST /api/scan`

Body: `{ "fetch": boolean }` — optional, default `false`.

- If `scanning` is non-null, await it and return its result.
- Otherwise set `scanning` to `scan({ baseDir, fetch })`, await it, assign to
  `current`, clear `scanning` in a `finally`, and return the inventory.
- Response: the fresh `Inventory`.

Reply with status 200. A scan takes ~15 s offline and much longer with
`fetch: true`, so do not add a route or request timeout.

### `POST /api/annotation`

Body:

```jsonc
{
  "id": "remote:github.com/me/x",   // required
  "status": "obsolete",              // optional, one of unknown|active|obsolete|archived
  "note": "superseded by y",         // optional
  "snoozedUntil": "2026-09-01"       // optional, ISO date string or null
}
```

The id is in the **body**, not the path, because ids contain `:` and `/` and
path-encoding them is a needless source of bugs.

Validation — reject with `400` and `{ error: "<message>" }`:

- `id` missing or not a non-empty string
- `status` present but not in `STATUSES` (imported from `core/state.ts`)
- `note` present but not a string, or longer than 2000 characters
- `snoozedUntil` present, not null, and not parseable by `new Date()`

Then:

1. `const annotation = await store.update(id, patch)` — only include keys that
   were actually present in the body, so a partial update cannot blank a note.
2. Normalise `snoozedUntil` to a full ISO string before storing.
3. Response: `{ annotation, project }` where `project` is the single re-evaluated
   project from a `refresh` call, or `null` when the id is not in the current
   inventory (a stale annotation for a project that has since moved).

Returning the recomputed project lets the frontend update one row without
refetching the whole inventory.

### `POST /api/script`

Body: `{ "action": "graduate", "ids": ["a", "b"] }`

- `400` when `action` is unknown or `ids` is not a non-empty array of strings.
- Look up the action in the registry, resolve the ids against the current
  inventory, and skip ids that do not resolve or that fail `action.appliesTo`.
- Build the script:

  ```sh
  #!/usr/bin/env bash
  # Generated by repo-inventory on <ISO timestamp>
  # Action: <label> — <description>
  # Projects: <n>
  #
  # REVIEW EVERY LINE BEFORE RUNNING. This script is never executed by the tool.
  set -euo pipefail

  ROOT="<inventory.root>"

  <concatenated action.script(project, root) lines>

  echo "done"
  ```

- Response: `{ script: "<text>", included: ["relPath", …], skipped: ["relPath", …] }`

`skipped` matters: silently dropping a project the user selected would be a lie.

### `GET /api/health`

Returns `{ ok: true, scannedAt: current?.scannedAt ?? null, scanning: scanning !== null }`.

Used by the CLI `dev` command to wait for readiness.

## Static file serving

Decide once at startup whether the frontend exists:

```ts
const indexPath = resolve(baseDir, "dist/index.html");
const hasFrontend = options.serveStatic && existsSync(indexPath);
```

When `hasFrontend` is true:

```ts
await app.register(staticPlugin, { root: resolve(baseDir, "dist"), prefix: "/" });
```

Add a catch-all so a page reload on any path returns `index.html`:

```ts
app.setNotFoundHandler((request, reply) => {
  if (!hasFrontend || request.url.startsWith("/api/")) {
    reply.code(404).send({ error: "not found" });
    return;
  }
  reply.sendFile("index.html");
});
```

`reply.sendFile` only exists once `@fastify/static` is registered, which is why
the handler checks `hasFrontend` first rather than assuming.

When the frontend is missing, log one clear line —
`dist/ not built — run: npm run build` — and keep serving the API.

---

## Error handling

- Wrap every handler body in try/catch. On an unexpected error reply `500` with
  `{ error: message }` and log the stack with `app.log.error`.
- Never let a rejected promise crash the process.
- Configure the logger as `{ logger: { level: "warn" } }` so a normal run is quiet.

## Verification

```bash
cd /path/to/repo-inventory
npm run typecheck
```

Then start it manually and exercise every endpoint:

```bash
node --input-type=module -e '
  const { startServer } = await import("./server/index.ts");
  console.log(await startServer({ baseDir: process.cwd(), port: 4747, serveStatic: false }));
' &
sleep 25

curl -s localhost:4747/api/health
echo
curl -s localhost:4747/api/inventory | jq '{projects: (.projects|length), rules: (.rules|length), actions: (.actions|length), scannedAt}'

ID=$(curl -s localhost:4747/api/inventory | jq -r '.projects[0].id')
echo "id=$ID"
curl -s -X POST localhost:4747/api/annotation -H 'content-type: application/json' \
  -d "{\"id\":\"$ID\",\"status\":\"obsolete\",\"note\":\"spec test\"}" | jq '.annotation'
curl -s -X POST localhost:4747/api/annotation -H 'content-type: application/json' \
  -d '{"status":"obsolete"}' -o /dev/null -w 'missing id status: %{http_code}\n'
curl -s -X POST localhost:4747/api/annotation -H 'content-type: application/json' \
  -d "{\"id\":\"$ID\",\"status\":\"nonsense\"}" -o /dev/null -w 'bad status: %{http_code}\n'

curl -s -X POST localhost:4747/api/script -H 'content-type: application/json' \
  -d '{"action":"graduate","ids":["'"$ID"'"]}' | jq -r '.script, .skipped'

# reset the annotation created by this test
curl -s -X POST localhost:4747/api/annotation -H 'content-type: application/json' \
  -d "{\"id\":\"$ID\",\"status\":\"unknown\",\"note\":\"\",\"snoozedUntil\":null}" | jq '.annotation'

kill %1
```

Checklist:

- [ ] `npm run typecheck` clean
- [ ] `/api/health` returns `ok: true`
- [ ] `/api/inventory` reports 50+ projects, 19 rules, 4 actions
- [ ] Setting `status: "obsolete"` returns the stored annotation with a fresh
      `updatedAt`, and the returned `project.suppressed` is `true`
- [ ] `missing id status: 400`
- [ ] `bad status: 400`
- [ ] `/api/script` returns a script starting with `#!/usr/bin/env bash` and
      containing `set -euo pipefail`
- [ ] The reset call leaves `data/annotations.json` containing `{}` for
      annotations — verify with `jq '.annotations' data/annotations.json`
- [ ] The server process was killed and port 4747 is free
